## 5. Локальная интеграционная проверка

Перед запуском убедиться, что локально выбраны актуальные ветки:

    backend: develop
    frontend: develop
    admin: develop (до production-merge) или main (после merge)

Запуск с чистой БД:

    cd /home/la_flame75/projects/hackatons/max-guide-submission
    cp .env.example .env
    docker compose down --volumes
    docker compose up --build -d
    docker compose ps
    ./scripts/verify-api.sh

Все основные контейнеры должны быть healthy, а seed должен завершиться успешно.

Это обязательная отдельная проверка — обычного браузера недостаточно.

- [ ] Бот открывается и отвечает.
- [ ] Кнопка бота открывает Mini App.
- [ ] Авторизация через MAX initData проходит.
- [ ] Сценарий проверен в мобильной версии MAX.
- [ ] Сценарий проверен в веб-версии MAX.
- [ ] Back button и закрытие Mini App работают ожидаемо.
- [ ] Поделиться/сохранить работает либо корректно обозначено как roadmap.
- [ ] Нет ошибок mixed content, CORS и cookies.
- [ ] Production URL работает по HTTPS.
- [ ] API работает по HTTPS.
- [ ] Сертификаты действительны.

Основной демонстрационный сценарий:

1. Открыть бота.
2. Перейти в Mini App.
3. Выбрать интересы или открыть ленту.
4. Найти место/событие.
5. Открыть карточку.
6. Сохранить объект или добавить его в маршрут.
7. Построить маршрут.
8. Вернуться к сохранённому результату в профиле.

## 10. Безопасность

Перед публикацией всех четырёх репозиториев:

- [ ] убедиться, что .env не отслеживается Git;
- [ ] проверить текущие файлы и Git history на токены, пароли и private keys;
- [ ] не добавлять node_modules, dist, volumes, дампы БД и локальные IDE-файлы;
- [ ] проверить .env.example: только безопасные placeholder-значения;
- [ ] перевыпустить любой секрет, который когда-либо попадал в Git;
- [ ] проверить права тестового администратора;
- [ ] проверить CORS/cookies для production-доменов;
- [ ] убрать debug endpoints и лишние подробности ошибок.

## 11. Финальный архив

Архив должен содержать зафиксированные версии четырёх репозиториев, но не
должен содержать:

- .git;
- .env;
- node_modules;
- dist/build;
- Docker volumes;
- локальные логи;
- IDE settings;
- временные файлы.

После создания архива вычислить:

    sha256sum ИМЯ_АРХИВА

Сохранить хэш рядом с архивом и в документации сдачи.
