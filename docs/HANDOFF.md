# Финальная передача проекта перед сдачей

Актуально на 29 сентября 2026 года. Этот документ — основная инструкция для
следующего разработчика и его AI-агента. Выполненные merge и базовая локальная
сборка сюда не включены: ниже перечислена только оставшаяся работа.

## Цель

Подать работающую Mini App «Непарадный Ставрополь» на хакатон: обеспечить
стабильный production-доступ через MAX, закончить материалы для жюри и
зафиксировать воспроизводимую версию исходников.

## P0 — обязательно до отправки

### 1. Развернуть и проверить production

- [ ] Развернуть backend из `master`.
- [ ] Развернуть frontend из `main`.
- [ ] Развернуть admin из `main`.
- [ ] Использовать production env; не публиковать секреты в Git.
- [ ] Проверить HTTPS и сертификаты для Mini App и API.
- [ ] Проверить healthcheck, БД, media-хранилище и логи.
- [ ] Проверить, что production не зависит от локальных Docker volumes.
- [ ] Подготовить простой rollback на предыдущий стабильный commit/tag.
- [ ] Оставить production включённым на весь период проверки жюри.

Минимальный smoke после deploy:

- `GET /api/health` успешен;
- регистрация и вход успешны;
- лента загружается;
- карточка места/события открывается;
- изображения доступны;
- событие создаётся, появляется в «Созданном» и повторно открывается;
- маршрут строится и открывается;
- admin входит и видит контент.

### 2. Проверить реальный сценарий внутри MAX

Проверка в обычном браузере не заменяет эту задачу.

- [ ] Бот отвечает.
- [ ] Кнопка бота открывает production Mini App.
- [ ] Авторизация через MAX initData проходит.
- [ ] Сценарий пройден в мобильном MAX.
- [ ] Сценарий пройден в веб-версии MAX.
- [ ] Back button/закрытие Mini App не ломают состояние.
- [ ] Нет mixed content, CORS и cookie-ошибок.
- [ ] Ссылки, сохранение и возвращение к маршруту работают ожидаемо.

Демонстрационный путь:

1. Открыть бота и Mini App.
2. Открыть ленту/карту.
3. Найти место или событие.
4. Открыть карточку.
5. Сохранить объект либо добавить его в маршрут.
6. Построить маршрут.
7. Вернуться к сохранённому результату.

- [ ] placeholder подтверждения прошлой победы на проверяемую ссылку/изображение.

После правок повторно экспортировать PPTX и PDF и проверить:

### 5. Уточнить обязательные артефакты по форме/FAQ

- [ ] Повторно открыть актуальную форму и правила конкурса.
- [ ] Проверить, требуется ли `DATA-API.yaml`; если требуется — подготовить по

### 6. Безопасность

Проверить все четыре репозитория, включая Git history:

- [ ] нет `.env`, токенов, паролей, private keys и webhook secrets;
- [ ] `.env.example` содержит только безопасные placeholders;
- [ ] ранее засвеченные секреты перевыпущены;
- [ ] тестовый admin имеет только необходимые права;
- [ ] обычный пользователь не получает admin-доступ;
- [ ] production CORS/cookies ограничены нужными доменами;
- [ ] debug endpoints и подробные production stack traces отключены.

Не считать простой поиск по текущим файлам полной проверкой истории. Использовать
доступный secret scanner либо проверить историю отдельно.

### 7. Зафиксировать финальную версию

После всех исправлений и production-проверки:

- [ ] обновить `docs/COMPONENT_VERSIONS.md` финальными SHA;
- [ ] убедиться, что рабочие деревья всех репозиториев чистые;
- [ ] поставить release-тег, например `hackathon-2026-final`;
- [ ] отправить теги в remote;
- [ ] не вносить изменения после фиксации без повторного smoke-test.

### 8. Архив и резервный доступ

- [ ] Создать архив фиксированных версий четырёх репозиториев.
- [ ] Исключить `.git`, `.env`, `node_modules`, `dist/build`, Docker
      volumes, логи и IDE-файлы.
- [ ] Посчитать SHA-256 архива.
- [ ] Сохранить архив и hash в доступном команде месте.
- [ ] Убедиться, что организаторы имеют доступ к репозиториям.

### 9. Независимая проверка и отправка

Другой человек должен с нуля:

- [ ] открыть ссылки из README;
- [ ] войти тестовым пользователем и администратором;
- [ ] пройти демонстрационный сценарий;
- [ ] проверить QR и PDF;
- [ ] проверить инструкцию запуска;
- [ ] убедиться, что в форме нет placeholder-текста.

При отправке:

- [ ] указать production Mini App;
- [ ] указать исходники/submission-репозиторий;
- [ ] приложить PDF и дополнительные обязательные артефакты;
- [ ] сохранить подтверждение и время отправки;
- [ ] после отправки не выключать и не менять production без необходимости.

## P1 — важная полировка

### Брендовые иконки

Во frontend есть `public/brand-logo.png`, но он пока не подключён. Стандартными
остались:

- `public/favicon.ico`;
- `public/logo192.png`;
- `public/logo512.png`.

Заменить их брендовой иконкой, проверить manifest, hard refresh и установленную
PWA. Не менять смысл/геометрию утверждённого логотипа.

### Пустая фотография карточки

На одной seed-карточке наблюдалась пустая область изображения. Проверить:

- media URL в API;
- наличие файла в production media storage;
- корректный Content-Type;
- fallback для отсутствующего изображения;
- отсутствие повторных/циклических запросов.

Это не связано с favicon или логотипом.

### Доказательство проблемы

Исторические продуктовые метрики отсутствуют. Если позволяет время:

- провести несколько коротких интервью с целевой аудиторией;
- записать метод, вопросы и честные выводы;
- не превращать цели пилота в якобы достигнутые показатели.

## Правила работы для следующего AI-агента

- Работать в отдельных `fix/*`, `feat/*`, `docs/*` ветках.
- Один логический fix — один понятный commit и PR.
- Не переписывать историю и не делать destructive reset.
- Не коммитить секреты и production credentials.
- Не менять API-контракт без необходимости.
- Перед изменением сверяться с README и документацией конкретного репозитория.
- После кода запускать релевантные build/tests и общий smoke.
- Обновлять этот файл и `SUBMISSION_CHECKLIST.md` только по фактически
  проверенным результатам.
- Не отмечать production/MAX-пункты выполненными по локальной проверке.

## Definition of Done

Сдача готова, когда одновременно выполнено следующее:

1. Production Mini App и API доступны по HTTPS.
2. Основной сценарий пройден внутри мобильного и веб-MAX.
3. Жюри получило рабочие ссылки и ограниченные тестовые доступы.
4. Презентация не содержит placeholders и открывается как PDF.
5. Финальные SHA/теги зафиксированы.
6. Все репозитории проверены на секреты.
7. Есть резервный архив и SHA-256.
8. Независимый человек прошёл инструкцию.
9. Форма отправлена, подтверждение сохранено.
