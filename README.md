# Непарадный Ставрополь — комплект конкурсной сдачи

«Непарадный Ставрополь» — мини-приложение и чат-бот в MAX, которые помогают
жителю или туристу найти локальные места и события, собрать маршрут и перейти
от идеи «куда сходить» к готовому плану в одном пользовательском сценарии.

Репозиторий объединяет запуск трёх самостоятельных компонентов без переноса их
Git-истории:

- `max-guide-backend` — NestJS API, PostgreSQL, MAX Bot API и Swagger;
- `max-guide-frontend` — пользовательское React-мини-приложение;
- `max-guide-admin` — интерфейс модерации контента.

Версии перечислены в [`docs/COMPONENT_VERSIONS.md`](docs/COMPONENT_VERSIONS.md).

## Быстрый запуск

Требования: Git, Docker с Compose v2 и свободные порты 3000–3002.
Репозитории должны лежать рядом:

```text
hackatons/
├── max-guide-submission/
├── max-guide-backend/
├── max-guide-frontend/
└── max-guide-admin/
```

Запуск всех локальных компонентов одной командой:

```bash
cp .env.example .env
docker compose up --build
```

Одноразовый контейнер `seed` добавит 101 тестовое место Ставрополья.
У 68 записей есть локальные фотографии. Повторный запуск безопасен.

Адреса:

- мини-приложение: <http://localhost:3001>;
- API: <http://localhost:3000/api>;
- Swagger UI: <http://localhost:3000/api/docs>;
- OpenAPI JSON: <http://localhost:3000/api/docs-json>;
- админское приложение: <http://localhost:3002>;
- health check: <http://localhost:3000/api/health>.

Для карты задайте `REACT_APP_YANDEX_MAPS_KEY` в `.env`. Без ключа
остальные экраны и API доступны, но Яндекс Карта может показать ошибку.

Остановка: `docker compose down`.

Полный сброс тестовых данных: `docker compose down --volumes`.

Проверка основного набора API:

```bash
./scripts/verify-api.sh
```

Подробности и ожидаемые ответы приведены в
[`docs/API_VERIFICATION.md`](docs/API_VERIFICATION.md).

## Основной сценарий проверки

1. Открыть чат-бота MAX и перейти в мини-приложение.
2. Открыть ленту или карту мест и событий.
3. Выбрать объект и открыть карточку.
4. Сохранить объект либо добавить его в маршрут.
5. Открыть собранный маршрут и просмотреть точки на карте.

Локально без MAX можно открыть <http://localhost:3001>, зарегистрировать
тестового пользователя и пройти аналогичный интерфейсный сценарий.

Перед сдачей раздел необходимо дополнить публичной ссылкой на выданного бота,
тестовой учётной записью и точным сценарием, проверенным внутри мобильной и
веб-версии MAX.

## Архитектура

```text
MAX bot ───────┐
               ├── NestJS API ── PostgreSQL
React miniapp ─┤       │
               │       └── локальное/S3-хранилище медиа
Admin React ───┘
```

Frontend и admin обращаются к API по относительному пути `/api`. Локальные
Nginx-контейнеры проксируют запросы в контейнер `api`. Backend отвечает за
авторизацию, контент, маршруты, события, медиа, MAX-интеграцию и admin API.

## Данные и интеграции

- PostgreSQL хранит пользователей, места, события, маршруты и состояния.
- Демонстрационные места — заранее подготовленные тестовые данные.
- Фотографии seed-набора хранятся локально; источники указаны в данных.
- Яндекс Карты требуют публичного API-ключа.
- MAX Bot API и MAX WebApp требуют выданных организаторами настроек.
- S3 поддерживается backend, но не требуется локально.

Тестовые данные не выдаются за прямую интеграцию с городской информационной
системой.

## Секреты

В этом репозитории нет рабочих токенов и паролей. `.env.example` содержит
только шаблонные значения. Настоящие секреты не должны коммититься.

## Известные ограничения

- локальная email-авторизация предназначена для воспроизводимой проверки;
- конкурсный сценарий нужно дополнительно проверить из выданного бота MAX;
- подготовленные места и расписания не обновляются автоматически;
- Яндекс Карта не работает без валидного ключа;
- `DB_SYNCHRONIZE=true` используется только в MVP-окружении;
- перед сдачей нужны стабильный HTTPS, тестовые доступы и итоговые commit hash.
